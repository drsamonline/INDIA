2 · Improving these models — and being honest about them

Most of these models are approximations, and some are rough. They are built from published dimensions and photographs by one person, not surveyed, and the table below says what each one actually is. Three levels are used:

  • measured — dimensions taken from a published survey and checked against the built geometry.
  • approximate — the right massing and proportions, with the ornament simplified or suggested.
  • study — a deliberate simplification, not an attempt at a reconstruction.

Spotted something wrong? Every monument page has a Report it link that opens a GitHub issue with the page and its level already filled in — a sentence and a source is enough. Open an issue.

If you improve a model, your name and a link go on this page and in the model itself. That is the deal, and it is the whole deal: open a pull request that changes one monument, say what you changed and where you got the dimensions, and your name is added to that monument's row here, to its entry in data/monuments.json, and to the header comment of its module file — so the credit travels with the code and shows on the page. There is no copyright assignment, no contributor licence agreement, and nothing to sign. CONTRIBUTING.md has the details.

5 · Software

  • three.js r169 — MIT licence. The renderer, the physical sky, the water and the post-processing passes all come from it.
  • OrbitControls, Sky, Water, EffectComposer, UnrealBloomPass, OutputPass and BufferGeometryUtils are part of three.js and are vendored in assets/vendor/three.
  • No other JavaScript libraries are used. The site has no build step and runs from any static file server.

7 · Measured dimensions

Each model is built to 1 unit = 1 metre. The figures behind every model, with a source per row, are in DIMENSIONS.md, together with the eight dimensions where the published sources disagree and the model had to choose.
